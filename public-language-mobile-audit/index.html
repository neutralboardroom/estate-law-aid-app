Public Language and Mobile UX Audit

Internal review screen for checking public pages before launch. It focuses on customer clarity, public/internal separation, mobile usability, and safe but non-alarming compliance language.

Public-page standards

  • No version, pilot, endpoint, API, scaffold, production-secret, owner-operations, provider-placeholder, or developer language on public pages.
  • Public copy should answer what the user can do, what is free, what is optional, and what is not safe to sign too early.
  • Internal pages are noindexed and removed from public navigation.
  • Mobile forms must use readable 16px inputs, 44px touch targets, and no horizontal overflow.
